# 0.4.1 连接状态与筛选布局

日期：2026-10-27。源代码、工具缓存与构建输出继续使用原定 E 盘目录。升级前源代码与配置已备份到 cache/claribar/backups。

## 修改

- 资源监控标题右侧保留一个操作按钮，移除原来并列且始终固定文案的授权/重连按钮。
- 根据真实采集进度显示“等待授权…”、“连接中…”、“读取中…”，过程中禁用按钮并显示进度环。收到普通权限实际采样后显示“授权硬件访问”；收到提升权限的实际采样后显示“重新连接”，旁边显示“硬件访问已授权”。
- 授权状态由实际快照确认，保存的启动偏好不会被当作当前授权成功。失败、取消及数据过期有各自状态文字，取消或提升失败后退回基础采集时保留说明。
- 概览页的硬件访问操作也使用相同的状态逻辑。
- 数量统计与“显示无读数通道”移动到筛选行右侧，与具体硬件筛选并列。
- 左侧类别筛选改为“全部类别”；右侧具体硬件筛选改为“全部硬件”，并增加各自的悬停说明。切换指标范围时更新可选硬件，原硬件不在新范围时清除旧筛选条件。

## 验证

- 原生模块、采集器、WinUI 应用最终构建：0 警告、0 错误。
- 普通权限六页面运行和自渲染检查通过。实际观察到 Connecting → Reading → Connected，普通会话的按钮为“授权硬件访问”且可操作。
- 读取实际 WinUI 布局坐标验证：按钮位于标题右侧；数量与复选框位于具体硬件右侧；所有控件位于可用宽度内。“全部类别”与“全部硬件”的实际选中值检查通过。
- 日常版本打开资源监控页面，根据实际提升权限采集数据验证“重新连接”文案和授权状态。

机器可读结果在 cache/claribar/logs：`claribar-sensor-controls-check.json`、`claribar-ui-smoke-user.json`、`claribar-connection-state.json`。其中 UI smoke 与布局检查使用基础采集，日常进程的连接状态由运行诊断单独记录。
