# 0.5.3 实际字形、行间距与垂直位置

## 实测尺寸

本机两个任务栏的 Win32 窗口、客户区及 DWM 扩展边界均为 48 个物理像素高，DPI 为 96（100% 缩放）。XAML 任务栏背景和托盘布局同为 48 个逻辑像素高。用户举例的 150/120px 未作为布局常量或比例使用。

原始记录：`E:\haoyue\cache\claribar\logs\taskbar-window-geometry.json`。

## 修复

0.5.2 使用 `TextLineBounds.Tight`，其行框只覆盖大写字母高度到基线，字形的上伸、下伸部分可以超出行框。仅检查行框的居中不能证明实际字形具有足够的行间距。

0.5.3 使用 DirectWrite 的字形外延和行基线测量可见字形，包含中文、重音及下伸字符。每行使用共同基线，按实际字形安排高度；行间预留 4 个逻辑像素的净空。文字使用完整行框绘制，通过单元格内的基线位置摆放字形。

内嵌监控每次读取当前任务栏背景在托盘中的实际范围；背景元素重建时重新获取。多行布局在可用空间内最多上移 2 个逻辑像素，靠近边缘时减少上移量，空间不足时缩小字体。预览复用相同的字形测量，并读取实际任务栏高度。

## 验证

两个实际任务栏上的 8 组字号、字体、布局组合全部通过，包括中文、`gjpq` 和重音字符。检查字形上下边界、行间净空、字号范围和文字省略状态；测试后的任务栏属性还原检查通过。

```powershell
& .\scripts\build-native.ps1
& .\scripts\probe-taskbar.ps1 -Apply -Centering
```

自带运行库的发布版本执行 `--smoke-test`，六个页面及两处字号编辑检查通过。随后运行像素检查：

```powershell
& .\scripts\verify-monitor-render.ps1
```

像素检查读取本程序实际渲染的 PNG，提取监控文字所在的两条字形区域，验证空隙、边缘留白和视觉中心。8、15、24 字号及下伸字符共四组全部通过，可见行间空隙为 4–6 个像素；考虑字体栅格化与像素对齐，视觉中心允许最多 2 像素误差。

记录：缓存目录 `logs\taskbar-centering-verification.json`、`logs\claribar-monitor-pixels.json`；图片位于 `artifacts\ClariBar\screenshots\monitor-alignment-*.png`。本次未使用外部键鼠自动化或重启 Explorer。

参考：[TextLineBounds](https://learn.microsoft.com/en-us/uwp/api/windows.ui.xaml.textlinebounds)、[DWRITE_OVERHANG_METRICS](https://learn.microsoft.com/en-us/windows/win32/api/dwrite/ns-dwrite-dwrite_overhang_metrics)。
