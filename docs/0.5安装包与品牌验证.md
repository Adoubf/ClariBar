## 安装包结构

- 文件：`artifacts/ClariBar/releases/ClariBar-Setup-0.5.0-x64.exe`，旁边有 SHA-256 校验文件。
- 内层是 Inno Setup 7.1.0 的 x64 中文/英文向导，跟随系统深浅色；外层为本项目的 C++ 引导程序，在提取安装数据前设置子进程 TEMP/TMP，使安装缓存默认位于 E 盘，完成后清理本次会话目录。
- .NET 10 x64 与 Windows App SDK 随应用发布，独立采集器也自带运行库。无需开发环境或全局 .NET。
- 默认软件目录：cache/claribar/programs/ClariBar；运行配置、日志、临时文件默认继续在 cache/claribar。向导可选择软件与运行数据目录，支持含中文的路径。
- 开始菜单和可选桌面快捷方式直接启动安装版 EXE；Windows 应用列表中提供卸载。
- 安装/升级/卸载通过本程序退出消息正常关闭运行中的澄栏，等待其互斥对象释放，不强制终止 Explorer。
- 安装器带有未修改且官方数字签名有效的 PawnIO Setup 2.2.0，未安装时可选择打开其官方向导。已有共享 PawnIO 不被替换或随澄栏卸载；本机继续使用既有 2.0.1 驱动。
- 任务栏适配模块在运行数据目录按 SHA-256 缓存后加载；安装目录中的原始 DLL 不直接加载进 Explorer，因此可以正常更新和卸载程序文件。缓存会按之前说明保留到 Explorer 自然退出；个人设置在卸载时保留。

## 发布与退出问题修复

实际安装测试发现当前 WinUI SDK 的 dotnet publish 没有带上应用自己的 XBF 和 PRI。已在 csproj 添加发布目标复制这些生成资源，并在打包前断言 App.xbf、MainWindow.xbf 和 ClariBar.pri 必须存在。修正后安装目录中的程序成功启动，实际基础采集与两个任务栏连接通过。

运行中卸载还发现采集器硬件关闭可能超过旧版 3 秒等待时间。现允许采集器在界面退出前完成关闭；安装器另用只读维护模块按完整 EXE 路径确认界面和独立采集器均已退出后才改动文件。卸载检查逐项核对全部 payload 文件均已删除，不只检查主 EXE。CMake 也显式跟踪内层安装包与图标资源依赖，保证重新打包时 C++ 引导程序嵌入的是最新 payload。

程序与安装包目前未使用商业代码签名证书签名；官方第三方下载已核对发布 SHA-256 和 Authenticode 签名。

## 复现

```powershell
& .\scripts\package.ps1
& .\scripts\verify-installer.ps1
```

`package.ps1 -SkipBuild` 复用已构建的 C++ 模块；发布步骤仍会执行，避免把旧依赖混入安装包。Inno Setup 位于 cache/claribar/programs/InnoSetup，全部发布中间文件在 cache/claribar/build/package。

完整安装回归使用新建的测试目录及独立运行数据目录，清除开发 PATH、指定不存在的 DOTNET_ROOT、移除 CLARIBAR_ROOT 后运行安装版本。验证安装后文件的 SHA-256、中文数据目录、真实采集/预览/任务栏、运行中覆盖升级与运行中卸载，并检查保留个人数据、移除注册项与测试快捷方式。结果保存到 logs/claribar-installer-validation.json。
