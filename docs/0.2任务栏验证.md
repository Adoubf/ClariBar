# 0.2.0 任务栏验证

日期：2026-10-27。系统 Windows 11 25H2 / 26200.9711，双显示器。

## 实际任务栏检查

使用 `scripts/probe-taskbar.ps1 -Apply -Extended -Watchdog`，通过本程序原生桥接读取 Explorer 中的真实 XAML 元素及属性，不以函数返回成功代替效果检查。

- 发现 2 个任务栏、4 个背景填充/边框、2 个时间及 2 个日期文字节点。
- 在两个任务栏的 `SystemTrayFrameGrid` 内实际插入 `ClariBarEmbeddedMonitor`，参与空间分配。
- 全透明时背景和边框的 SolidColorBrush 为 `#00000000`；半透明着色测试为 `#80446688`。着色测试期间任务栏会临时呈蓝灰色。
- 时间与日期使用不同颜色；4 项监控分别读回各自颜色。系统图标匹配到网络、声音、输入法各 3 个字形/路径节点（节点数不等于物理图标数）。分别设置不同颜色后实际属性符合配置。
- 用 6 项指标区分布局：单行 6 列 × 1 行、双栏 2 列 × 3 行、双行 3 列 × 2 行；分别读回 16、8、12 的字号。
- 默认内嵌父 Grid 的 `IsHitTestVisible=false`；显式关闭穿透时读回 true。
- 关闭功能后：插入区域为 0、修改属性为 0、时间与日期颜色与测试前一致。
- 暂停主进程心跳后自动移除插入区域、恢复所有修改，失联恢复检查通过。

上述是控件属性与结构的真实集成检查。Computer Use 在此 WSL 会话的入口仍有路径校验问题，未把这些检查称为桌面像素截图检查或完整人工鼠标覆盖。

## 故障与恢复记录

早期诊断原型试验在 15:48:53–15:49:10 期间出现过 4 次 Explorer 自动重启。随后修正 COM 导出，最终使用的 Explorer PID 为 15652；修正后连续的读取、应用、布局切换与恢复验证没有再次重启。没有主动结束或重启 Explorer。

诊断树也修复两处问题：系统日期字符串中的内嵌 NUL 导致文本截断；重复接入时需等待周期诊断树生成后再保存测试基线。这两处修复后完整属性、布局和恢复断言通过。

适配 DLL 为回调安全固定驻留当前 Explorer 进程；还原后闲置，Explorer 自然退出时才卸载。无需系统注册或自启动项。不要删除当前仍由 Explorer 加载的哈希适配目录。

## 记录位置

全部位于 `E:\haoyue\cache\claribar\logs`：

- `taskbar-property-verification.json`：透明、颜色、默认穿透和还原的断言。
- `taskbar-layout-verification.json`：三种布局、字号、独立图标颜色、半透明颜色和命中测试。
- `taskbar-watchdog-verification.json`：心跳失联恢复。
- `taskbar-tree-applied.txt`、`taskbar-tree-layout-0.txt` 至 `-2.txt`、`taskbar-tree-restored.txt`：实际控件属性。
- `claribar-ui-smoke.json`、`claribar-app-taskbar-check.json`：WinUI 页面和实际程序接入检查。
- `claribar-checks.json`：配置、无效数据及真实采集 IPC 检查。

此前 0.1.0 的管理员采集验证仍保留在 `claribar-ui-smoke-admin.json`；0.2.0 本轮使用普通权限测试任务栏和基础采集，不重复弹出 UAC。
